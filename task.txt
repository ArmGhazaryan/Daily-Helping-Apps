Task Goal:
Perform a systematic, module-by-module QA audit across the project to detect and fix any functional bugs (especially post-refactoring regressions) and responsive design issues across Desktop, Tablet, and Mobile viewports.

Execution Strategy (CRITICAL TO AVOID TIMEOUTS):
- Audit and fix ONE page/module at a time sequentially (start with the main English Flashcards module, then proceed one by one through the remaining HTML/CSS/JS module pairs).
- Apply ONLY targeted, surgical edits to the specific lines that need fixing. NEVER rewrite entire files from scratch.
- STRICT RULE: DO NOT use terminal commands. Edit files directly.

AUDIT CHECKLIST FOR EACH MODULE:

1. Post-Refactoring Functional & Bug Check (HTML <-> CSS <-> JS Sync):
   - Verify that every button, modal trigger, form, and tab in the HTML has a valid, working `addEventListener` or event delegation handler in its corresponding `.js` file (check for broken selectors, typos in `id`/`class`/`data-*` attributes, or `null` DOM references).
   - Verify that visibility utility classes (`.is-hidden`, `.is-visible`, `.is-active`, `.has-note`) exist in the CSS and toggle properly without conflicts (e.g., `display: flex` vs `display: none !important`).
   - For English Flashcards specifically: confirm that card flipping, Next/Prev navigation, Favorites filtering, all 4 Practice Zone mini-games, and Supabase `user_notes` (load, save/upsert, delete, adaptive top-left badge/modal) work without errors.

2. Responsive Design & Layout Check (Mobile 360px–480px & Tablet 768px):
   - Check CSS media queries (`@media (max-width: 768px)` and `@media (max-width: 480px)`) for every page.
   - Eliminate any horizontal overflow (`overflow-x`), clipped text, or overlapping elements on small screens.
   - Ensure multi-column grids, filter sidebars, navigation bars, game cards, and modals stack cleanly (`flex-direction: column` or 1-column grid) with proper padding and touch-friendly button sizes on mobile.
   - Ensure flashcard front/back faces fit cleanly within mobile viewports without awkward internal scrollbars.

3. Reporting:
   - After auditing and fixing each module, briefly list the exact bugs or responsive issues found and fixed before moving to the next module.
